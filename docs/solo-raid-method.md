## 세션을 시작할 때

실무는 새 세션에서 한다 (사용자 2026-10-28 — 맥락 창을 아끼려고). 사용자는 모든 작업 세션에 같은 한 줄을 붙인다:
「docs/solo-raid-method.md 진행표에서 다음 차례 WP를 맡아 진행해. 실무는 Sonnet 서브에이전트로.」

1. `AGENTS.md` → 이 문서의 「1. 원칙」·「진행표」 → 맡은 작업 묶음(WP) 카드를 읽는다.
   **맡을 WP 고르기:** 사용자가 WP를 지정하면 그것. 아니면 진행표에서 상태가 「대기」이고 기다리는 앞 WP가 끝난 것 중 맨 위의 것.
   한 세션은 WP 하나를 끝까지 하고, 맥락에 여유가 있어도 다음 WP로 넘어가지 않는다 (진행표 줄이 둘로 나뉜 WP는 한 줄씩).
2. 진행표에서 맡을 WP의 상태를 「진행」과 세션 주소로 바꿔 **먼저 커밋·push**한다 (다른 세션과 겹치지 않게 — push가 충돌하면 fetch해 진행표를 다시 보고 다른 WP를 고른다). 공용 도구를 고치는 WP2는 한 번에 한 세션만 한다.
3. 환경: `pip install -r tools/solo_raid/lab7/requirements.txt` (WP0이 만든다). 컨테이너는 세션마다 새로 받으니 매번 한다.
4. 끝낼 때: 산출물 커밋 → 진행표·맡은 WP 절 갱신 (상태 「끝」, 커밋, 다음 세션이 알아야 할 것 한두 줄) → 「바뀐 기록」 한 줄 → `git fetch origin main && git merge origin/main` → `git push origin HEAD:main`.
   사용자에게는 한 일·결과·다음 차례 WP를 짧게 답한다. 계획을 바꿨으면 바꾼 곳과 까닭을 이 문서에 적고 답에도 쓴다.

## 1. 원칙 (사용자 지시)

1. **당분간 이 레포의 할 일은 새 방법 찾기다** (2026-10-28). 진행 중 시즌의 예측은 관심사가 아니다.
   운영 일(자동 수집 켜기·진행 중 예측·모델 파일·웹 반영)은 **사용자가 지시할 때만** 한다. 에이전트가 먼저 판단해 꺼내거나 권하지 않는다 (2026-10-28).
   계획·보고에 진행 중 시즌의 일정·대비책을 넣지 않는다.
2. **방법은 널리 쓰는 것을 빌린다** (2026-10-28 — 「AI가 임의로 방법을 만들지 말고 기존에 널리 쓰는 방식을 차용하라는 뜻으로 가이드를 만들었다. 더 적절한 비슷한 계열이 있으면 써도 된다」).
   직접 만드는 것은 그 틀에 넣는 입력(게임 규칙에서 오는 제약, 자료 종류별 오차 크기)으로 줄인다.
   표준 틀로 안 되는 자리가 나오면 표준 대안을 먼저 찾아 적고, 그래도 직접 만들어야 하면 까닭을 적어 사용자에게 알린다.
3. **관측은 그 신뢰도대로 쓴다** (2026-10-20·10-28). 정확한 관측(기계 시각 사진)은 지나야 하는 점으로, 시각이 불확실한 관측은 그 불확실성대로,
   한쪽으로 치우친 관측(게시 시각만 있는 사진)은 치우침을 모형에 담아서 쓴다. 가중치로 가깝게·멀게를 조절하는 꼴로 풀지 않는다.
4. **시험 시즌은 따로 두지 않는다 — 개발 검증만** (2026-10-28 사용자 결정). 결과는 언제나 「개발 검증」이라 부르고 낙관 위험을 함께 적는다.
   대신 [4.4](#44-검증-설계)의 선택 편향 줄이기를 지킨다.
5. **공용 도구를 고쳐도 된다** (2026-10-28 — 순서표 2 구조 정리·4 도구 고침 포함). 자료가 바뀌면 F도 같은 자료로 다시 내서 견준다 ([4.5](#45-같은-자료로-견준다)).
   운영 예측 코드(`predict.py`·`predict_run.sh`)와 모델 파일은 고치지 않는다 — F를 그대로 재현해야 기준이 된다.
6. **모델 나누기** (2026-10-28): 설계·판단은 Opus 세션, 코드 작성·반복 계산·점검은 Sonnet 에이전트(Agent 도구 `model: sonnet`), 사진 판독은 지금처럼 Haiku.
   주로 Sonnet으로 도는 **Workflow 도구**는 AGENTS.md대로 그 세션에서 사용자 허락을 받는다.
7. **가이드 절차를 따른다.** 방법 선택은 AI의 책임이다 (§0-1, 사용자에게 모델·튜닝 값을 고르게 하지 않는다). 기준선과 후보 2~3개부터 (§0-5),
   성공 기준은 결과 전에 (§1.1), 후보·규칙은 계산 전에 적고 커밋 (사전 고정), 시도한 것은 모두 기록 (§5-7), 보고는 §6 꼴과 §5 12항목.
   어느 후보도 충분하지 않으면 「현재 데이터로 결론 부족」이라고 보고한다 — 그것도 결과다.

## 2. 문제 (가이드 §1)

- **결정.** 시즌 진행 중 시점 T에서 T까지 게시된 자료만으로 그 시즌 **한섭 최종 컷**을 맞히는 방법을 고른다.
  주 목표 1·3·10%, 함께 내는 것 0.5·2·5%. 출력은 중앙값과 80% 구간(예측 분포). 일섭·글섭은 보고만 한다 (라벨 관측이 적다).
- **독립 표본은 시즌이다.** 개발 시즌 S19~S42 24개, 맞힐 시즌 S21~S42 22개 (앞 시즌이 둘 이상인 시즌 — criteria_v2).

|---|---|---|
| Q1 | 목표 | 예측 (미래 시점 — 같은 시즌의 끝) |

### 2.1 성공 기준 (결과 전에 — 2026-10-28 사용자 결정 「초반과 막판을 함께」를 이어받는다)

- **주 지표 score** = ½ × (T 18·24·36·48의 시즌 평균 |e|) + ½ × (T H−12·H−6·H의 시즌 평균 |e|), 한섭 1·3% 칸 평균.
  e = 예측 중앙 ÷ 정답 − 1. 10%는 같은 셈을 따로 한다. 정의는 5.3 B 사전 고정과 같다 (`lab6/e_53s.py`).
- **지킬 조건** (5.3 B와 같은 정의): g1 중앙이 하한보다 낮은 칸 0 · g2 시즌 끝(T = H) 허용(1·3% ±2%, 10% ±3%) 밖 수가 F 이하 ·
  g3 최악 시즌이 F의 최악보다 0.5%p 넘게 나쁘지 않음 · g4 80% 포함이 두 창 각각 0.70 이상.
- **의미 있는 최소 개선은 score 0.3%p**다 (5.3 B와 같음). 그 안이면 「차이 불분명」 → 단순한 쪽 (순서는 사전 고정 때 적는다, 가이드 §4-5).
- **함께 보는 표준 지표** (고르기에 쓰지 않고 보고만): CRPS(예측 분포 전체의 점수), 80% 구간 폭, T별 곡선(T6~12 포함).
- **「점을 지나는가」 점검**은 고르기와 따로 본다 → [4.3](#43-점을-지나는가--관측-층-점검-고르기에-안-씀).

## 4. 방법

### 4.1 모형의 뼈대 (모든 후보 공통)

- **숨은 곡면.** 시즌 s, 챌린지 시작 후 h시간에 점수 x인 사람의 한섭 % P_s(x, h). 같은 것을 뒤집은 컷 C_s(q, h)로 써도 된다 —
  서로 역함수라 하나만 모형으로 두고 다른 쪽은 계산한다 (어느 쪽인지는 WP3 명세에서 정한다. 관측 가능도는 P 쪽, 목표는 C 쪽이 자연스럽다).
  제약: x가 크면 P가 작다 · 같은 x의 P는 h에 따라 줄지 않는다 · k위 점수는 줄지 않는다.
- **관측 층.** 관측 하나의 가능도 = 서버 혼합 × 오염 혼합 × (숨은 촬영 시각을 시각 모형으로 적분한) 곡면 위 % 표시 구간의 확률.
  표준 부품의 조립이고, 후보 M1~M3이 같은 코드(`lab7/obs_model.py`)를 쓴다. 3장의 표가 부품 목록이다.
- **시즌 사이 층.** 맞힐 시즌보다 앞 시즌들의 곡면에서 이번 시즌의 사전분포(곡면 모양·남은 시간의 상승)를 얻는다 — 경험적 베이즈 또는 계층 모형.
  시대 흐름(분석 4.1 「곡선 모양이 시즌 순서에 따라 평평해진다」)은 추세 항 대신 「최근 k시즌」 변형으로 본다.
- **예측.** 사후분포의 C_s(q, H) — 중앙·80%·95%. 구간은 사후분포에서 바로 나온다. 따로 넓혀야 맞는다면 모형이 틀렸다는 신호로 적고 원인을 본다 (넓히기로 덮지 않는다).
- **계산 도구: NumPyro (JAX, CPU)의 NUTS.** 고른 까닭: pip만으로 설치되고(2026-10-28 내려받기 확인) 컴파일이 없어 세션마다 새 컨테이너에서 바로 돈다,
  칸 수천 개를 반복하기에 CPU에서 빠르다. Stan(cmdstanpy)도 같은 모형을 쓸 수 있는 표준 도구다 — NumPyro에서 막히는 자리가 있으면 바꾼다.
  숨은 시각 적분은 1차원 구적. 칸마다 수렴 점검(R-hat < 1.01, 발산 0, ESS)을 적는다. 너무 느리면 라플라스·변분 근사를 조건부로 쓴다 (같은 칸에서 MCMC와 견준 뒤).

### 4.3 점을 지나는가 — 관측 층 점검 (고르기에 안 씀)

- **A 점 잔차.** 맞춘 곡면에서 A 점이 % 표시 구간 밖으로 벗어난 정도. 오염으로 분류된 점은 목록(`r7/flag_*.json`)으로 내서 자료 점검으로 돌린다.
- **지금 컷 맞히기 (LOO).** T마다 직전 6시간 A 점을 하나씩 빼고 나머지로 그 점의 %를 예측 → PIT(예측 분포에서 실제 값의 분위)·포함률.
  미래 불확실성 없이 관측 층과 곡면만 시험한다.
- **C 시각 모형 점검.** C 사진의 사후 촬영 시각 분포를 top7 구간·글 속 시각과 견준다.
- **사후 예측 점검 (PPC).** 모형에서 뽑은 자료에 순서 모순·같은 점수 % 역행이 실제 자료만큼 나오는지.

### 4.4 검증 설계

- **앞 시즌 → 다음 시즌** (criteria_v2와 같음). 맞힐 시즌 s의 시즌 사이 층과 모형 조정값(커널 길이·사전분포 폭 등)은 s보다 앞 시즌에서만 배운다 — 시간 순 nested.
  이번 시즌 자료는 T까지 게시된 것만 쓰고, T 절단 사본(`backtest.trunc_state` — 서버 라벨·top7이 뒤 글을 보지 않게 1단계를 다시 돈다)으로 만든다.
  관측 오차 크기(게시 지연 등)도 T에 실제로 쓸 수 있는 것만 쓴다 — 앞 시즌 + 이번 시즌 T까지의 A 사진 (WP1에서 시즌마다 달라지는지 보고 정한다).
- **T 격자.** T6~T120 6시간마다 + H−12·H−6·H (S28 118·124·130, S38 101·107·113).
- **시험이 없으니 선택 편향을 줄인다.**
  1. **조정 시즌 6개 — S22·S26·S30·S34·S38·S42** (4시즌마다, 시대를 고루). 모형 개발·디버깅·설정 고르기는 이 시즌들에서만 본다.

  2. 사전 고정: 후보·설정·고르기 규칙을 계산 전에 적고 커밋한다 (WP5).
  3. 시도 기록: 모든 실행을 `r7/attempts.md`에 적는다. 격자·후보를 늘리면 까닭을 적는다.
  4. 결과 이름은 「개발 검증 (22시즌, 조정 6 포함)」이다. 시험 성능이라고 부르지 않는다.

**1. 곡면의 꼴 — 최종 컷 곡선 × 침수, 두 함수로 나눔 (분리형)**

- 최종 컷 곡선: ln C_s(w) = a_s − ∫₀ʷ exp(r_s(v)) dv. a_s = ln(최종 3% 컷), r_s = 컷이 %를 따라 떨어지는 기울기의 로그.
- 침수: 점수 y의 시각 u의 log10 % = (그 점수의 최종 log10 %) − P_s(u), P_s(u) = ∫ᵤ¹ exp(ℓ_s(v)) dv (log10 단위 — 2.5의 P와 같은 것).
- **Q5의 세 제약이 꼴에서 저절로 선다.** exp > 0이라 점수가 높으면 %가 좋고, P가 u를 따라 줄며 P(1) = 0이라 같은 점수의 %는 줄지 않고 k위 점수도 줄지 않는다
  (컷 C_s(q, u) = C_s(q·10^{P_s(u)}, 1)이 u를 따라 는다). 양수 함수의 적분으로 단조를 박는 것은 단조 함수 추정의 표준 구성이다 (Ramsay 1998). 그래서 계획 4.2의 C2(도함수 가상 관측)는 필요 없어진다.
- **분리형의 근거.** P는 같은 일차 안에서 지금 %에 거의 평평하다 (2.5, x 의존이 수준의 0.08~0.21) · 같은 사람의 ΔP가 단면 P와 같은 모양 (2.6) · 시즌 차이의 제1 성분이 몫 99%이고 그것이 침수 배수 (4.2b).
  남는 x 의존은 M1에서 P·exp(β·(z_fin − log10 3))로 넣고 빼 본다 (F의 bx 자리, 7절 ②).
- **목표** = C_s(q, 1) — 곡선 위의 값이라 목표 % 사이 단조도 저절로 선다. 하한은 넣지 않는다 (3장 — g1로 점검).
- 계산: w 격자(0.1~40%, 120점)·u 격자(0.02~1, 200점, 앞쪽 촘촘)에서 누적 사다리꼴, 관측 자리는 선형 보간. M1은 닫힌 꼴을 쓴다.

**2. 관측 층 (`lab7/obs_model.py` — M1 세션이 만들고 M2·M3이 가져다 쓴다)**

- **쓰는 줄.** 관측 표의 kind A·B·C 가운데 `lo_reason` None·`rep` True (T까지 게시, 시각 거르기 통과, 같은 사람·같은 % 대표). `mono_drop`은 무시한다 — 서버 혼합이 맡는다.
  라벨 일섭·글섭 줄도 넣는다 (그 성분의 모수를 잡아 미상 줄 나눔을 돕는다). 글로만 적은 %는 본안에서 뺀다 (WP4 변형, 넣으면 1c 꼴 그대로).
- **관측 하나의 가능도.** L_i = Σ_k π_ik · [(1 − ε) · Σ_n ω_in · Pr(z_i ∈ I_i | y_i, t_in, 성분 k) + ε · f_c(z_i)]
  - % 구간 I_i = [log10(p − 0.005), log10(p + 0.01)) (1f). Pr = Φ((hi − μ)/σ) − Φ((lo − μ)/σ), μ = 곡면 값 (구간 중도절단 정규).
  - 잔차 σ(u) = √(σ0² + (ρ·P(u))²) — F의 잔차 꼴(fit_prior σ(h))과 같다. 곡면 모형이 다 못 담는 몫이고, 정확한 점은 σ0 안에서 지난다. 초반 퍼짐이 큰 것(2.2 첫 24시간 0.121)을 ρ가 받는다.
  - 오염: 칸마다 ε ~ Beta(1.46, 98.54) (1d 중심 사전), f_c = log10 % 잔차의 라플라스(척도 0.34) 밀도 × 구간 폭.
- **숨은 촬영 시각.** 줄마다 노드 t_in과 무게 ω_in을 모형 밖(numpy)에서 미리 낸다. 지지 [L_i, U_i]: L = max(0, h_lo, h_lo_top7), U = min(hp, h_hi_top7, H) — **top7 구간을 읽는다** (WP1 ②).
  노드는 지지로 자른 분포의 (j − ½)/K 분위, 무게 1/K (분위 구적). 지지 밖 몫은 버리고 다시 정규화한다.

  | 종류 (`t_basis` 묶음은 `err_1b.group_of`) | 촬영 시각 | 노드 |
  |---|---|---|
  | A | h (분 단위) | 1 |
  | B timer | h − 24k: k = 0 (1 − 0.0195), k ≥ 1은 0.0195 × 기하분포 (k ≥ 2 몫 0.43) — 오염이 아니라 하루 단위 성분 (WP1 ③) | k마다 1 |
  | B now | h − L, L ~ 1b 로그정규 혼합 (중앙 1.5분 + 꼬리 7%) | K |
  | B clock | h − e, e ~ 1b 정규 σ 2.2분 + 넓은 성분 (12시간 다른 후보 등) | K |
  | B hours_ago·day·other, C | hp − d, d ~ 1a 2성분 로그정규 — 맞힐 시즌 s는 `expanding[s]` (앞 시즌만) | K |

- **서버 혼합 π_ik.** 라벨 줄 = 라벨 서버 1 − e_근거 (1e `beta_central` 평균), 나머지 몫은 사이트 몫대로. 미상 줄 = 사이트별 한섭·일섭·글섭 몫 φ_site — **칸마다 추정**한다 (사전 = 1e 디리클레).
  일섭·글섭 성분 = 한섭 곡면에서 점수 비 δ_k (ln, 그 서버 컷 ÷ 한섭 컷), 침수 배수 exp(ψ_k), 컷 기울기 배수 exp(κ_k) 셋만 다르다. 사전은 3절 시즌 사이 층에서.
- **사람.** 사람 효과는 두지 않는다 — 곡면이 점수 → %를 정하므로 같은 사람의 다른 시점은 시각·표시 오차 말고 남는 공통분이 없다. 중복은 `rep`로만 줄인다 (3장 표).
- **내는 것 (4.3).** 줄마다 사후 오염 확률이 0.5를 넘는 목록 `r7/flag_{M}_{판}.json` (자료 점검으로), 미상 줄의 사후 한섭 확률, C 줄의 사후 촬영 시각 (top7·글 속 시각과 견준다).

**3. 시즌 사이 층 (`lab7/hier.py` — M1 세션) — 두 단계 경험적 베이즈**

- **1단계 (끝난 시즌마다 한 번, 후보마다).** 끝난 시즌 전체 관측 표(`obs_table.py --full`)를 같은 관측 층·같은 꼴로, 약한 사전(5절)으로 맞춰 시즌 모수 θ̂_j(사후 평균)·V_j(사후 공분산)를 낸다.
  종료 뒤 화면 줄(`day_lo` = post)은 촬영 t = H 관측으로 넣는다. **정답 표(answer_key)는 쓰지 않는다** — 정답은 채점에만. 결과 `r7/stage1_{M}_{판}.json` (24시즌, 커밋).
- **2단계 (맞힐 시즌 s마다).** 창 W(s) 안의 앞 시즌 j로 θ̂_j ~ N(μ, Σ + V_j) — 측정오차가 있는 무작위 효과 메타분석의 베이즈판 (표준 정규-정규 계층 모형).
  Σ = diag(τ)·Ω·diag(τ), Ω ~ LKJ(2), τ ~ HalfNormal(5절), μ ~ 넓은 정규. NUTS로 풀어 새 시즌 θ의 사후 예측을 평균·공분산이 같은 정규로 맞춰 그 시즌 칸의 사전으로 쓴다
  (초모수 불확실성이 공분산에 들어간다 — 교훈 ④. 시즌이 적은 S21~S23은 사전이 넓어진다). 1단계 V_j가 큰 시즌(S19 — 4.1 H4)은 저절로 가볍다.
  침수 크기와 10%/3% 모양이 함께 움직이는 것(4.2, ρ −0.61)은 Ω의 상관이 받는다.
- **규모 a_s는 따로** — a_s ~ N(â_{s−1}, τ_a²): 직전 시즌 수준에서 출발하는 국소 수준 모형 (무작위 걷기, 기울기 없음). τ_a는 창 안 연속 시즌 차이에서 (V를 빼고).
  Z0와 같은 정보다. 3% 컷 규모는 시즌 순서를 따라 오르지만(4.2 ρ 0.96) 시즌 순서 기울기 항은 넣지 않는다 (사용자 결정). 초반에는 이 사전보다 P_s의 사전(침수 크기 sd 약 0.15)이 컷을 정한다.
- **창 W(s).** k ∈ {4, 6, 10, 앞 시즌 전체} 중, s보다 앞 시즌들 안에서 한 시즌씩 앞으로 가며 θ̂_j의 예측 로그 밀도 합이 가장 큰 k (시간 순 교차검증). 평가할 앞 시즌이 3개 미만이면 전체.
  시대 흐름(4.1 H6 — 모양이 평평해짐)은 이 창이 받는다. 고정 k 셋은 민감도로 보고만.
- **대안.** 맞힐 시즌과 앞 시즌을 한 모형으로 함께 맞추는 완전 계층 모형 — 같은 답에 가깝고, 칸마다 시즌 수십 개를 다시 맞춰야 해 느리다. 7절 ⑦에서 한 시즌 몇 칸만 견준다.
- **조정값은 모두 앞 시즌에서만 나온다** (4.4): μ·Σ·τ_a·창 k·M2 커널·M3 주성분·게시 지연. 예외 둘 — 오염(1d)·서버 착오(1e) 사전은 WP1이 24시즌으로 잰 값을 그대로 쓴다.
  정답을 보지 않은 관측끼리의 값이고 시즌 변동이 사전 폭에 들어 있어서다. 4.4 문장과 다른 점이라 결과 보고에 낙관 위험(작음)으로 적는다.

**4. 후보별 꼴**

| | 컷 기울기 r_s(w) | 침수 | 이번 시즌 모수 (사전은 3절) |
|---|---|---|---|
| **M1** 매개변수 | r0 + r1·w → ln C = a − e^{r0}·((q/3)^{r1} − 1)/r1 (q의 Box–Cox 꼴. r1 → 0이면 거듭제곱, r1 > 0이면 위쪽이 평평해 점수 상한이 있다) | P = m·p0(u; η)/p0(0.4; η), p0 = −log10 F(u) — m = P(0.4)가 침수 크기(48시간 자리), η는 모양만. F 후보 둘: **f2pow** w·u^p + (1 − w)·u^q (F와 같은 꼴, 3모수) · **Kumaraswamy** 1 − (1 − u^α)^β (2모수) — 7절 ①로 고름 | a, r0, r1, ln m, η, ln σ0, ln ρ, (β), 일·글 δ·ψ·κ, 사이트 몫 |
| **M2** GP | r̄(w) + f1(w) | ln(−dP/du) = ℓ̄(u) + ln m + f2(u) | a, ln m, f1·f2 기저 계수, σ0·ρ, 일·글, 사이트 몫 |
| **M3** 함수형 주성분 | μ_r(w) + Σ ξ_k·φ_k^r(w) | ℓ_s(u) = μ_ℓ(u) + Σ ξ_k·φ_k^ℓ(u) (같은 ξ) | a, ξ_1..K, σ0·ρ, 일·글, 사이트 몫 |

- **M2.** 평균 함수 r̄·ℓ̄ = 그 시즌 2단계에서 나온 M1 평균 곡선 (ℓ̄는 P(0.4) = 1로 정규화, 계획대로 수준 a·ln m만 이번 시즌에 맞춘다). f1·f2는 HSGP (힐베르트 공간 근사 GP — Solin·Särkkä 2020, Riutort-Mayol 외 2023),
  Matérn-5/2, 기저 20개, 경계 배수 1.5. f2는 u 격자 평균을 0으로 묶는다 (ln m과 겹치지 않게). 길이·크기는 앞 시즌 1단계 M2 적합(약한 사전 — 길이 역감마, 크기 반정규)의 창 안 중앙.
  맞춘 길이가 그 기저로 나타낼 최소 길이보다 짧으면 기저를 늘린다 (Riutort-Mayol 진단). 로그 기울기에 GP를 얹으므로 단조는 저절로 선다.
  4.2b의 「막판 몇 시간이 시즌 배수와 따로 움직인다」와 2.4의 밤 활동은 f2가 받는다.
- **M3.** PACE(Yao·Müller·Wang 2005)를 베이즈 관측 층에 얹은 꼴. 앞 시즌 곡선 [r_j(w 격자 12점), ℓ_j(u 격자 12점)]은 1단계의 **P-스플라인 적합**에서 가져온다
  (3차 B-스플라인 r 7개·ℓ 8개, 계수에 2차 무작위 걷기 사전 — Lang·Brezger 2004. M2를 기다리지 않으려고 M3이 따로 둔다).
  창 안 시즌들의 공분산에서 평균 사후 공분산(V̄)을 뺀 뒤 (PACE의 잡음 처리) 주성분을 낸다. K = 설명 몫 90%에 처음 닿는 수, 최대 3, 시즌 수 − 2 이하. ξ_k ~ N(0, λ_k).
  로그 기울기에서 주성분을 내므로 단조는 저절로 선다. 4.2b대로라면 제1 성분 ≈ 침수 배수, 제2가 시간 모양이다.
  - **M3 구현에서 더한 선택 (WP3b M3 세션, 2026-10-29 — 계산 전).** ① 기저: r는 w ∈ [ln(0.1/3), ln(40/3)]에 같은 간격 매듭, 밖은 끝값 그대로(상수 외삽).
    ℓ는 s = √u ∈ [√0.02, 1]에 같은 간격 매듭 — 침수가 빨리 변하는 초반을 촘촘히 (u 등간격이면 첫 24시간에 매듭이 하나). RW2는 계수 차분에, 그 위에 계수마다 넓은 정규(r N(ln 0.3, 1.5²) · ℓ N(ln(0.2/0.6), 2²) — 1절 사전과 같은 자리)를 곱해 고유 사전으로.
    ② 적분 격자는 관측 %가 0.01~100%라 w를 0.005~100%(160점)로 넓히고 그 밖 점수는 끝 기울기로 직선 외삽. 평가 격자 w12·u12도 같은 축(w 등간격 0.1~40%, √u 등간격).
    ③ 1단계 θ̂ = [a, ln σ0, ln ρ, 일·글 δ·ψ·κ, r(w12), ℓ(u12)] (33개)의 사후 평균·공분산 → `r7/stage1_M3_D1.json`. 일·글 성분은 M1과 같은 자리(a + δ, r + κ, ℓ + ψ).
    ④ 2단계: 곡선 24개 값의 주성분은 PACE대로 내고, 평균을 J시즌에서 추정한 몫으로 ξ_k 분산에 (1 + 1/J)를 곱한다 (정규 표본의 예측 분산). 주성분은 스플라인 계수로 되돌린다 (최소제곱 — 곡선이 기저 공간 안이라 정확).
    창 k는 3절 후보 넷 중 곡선 벡터의 시간 순 예측 로그 밀도로 고른다 — 밀도는 확률 PCA(Tipping·Bishop 1999: 버린 고윳값 평균을 등방 잔차로) + V_j. 그 밖 모수(ln σ0·ln ρ·일·글)는 같은 창으로 `hier.prior_for(k_fixed=k)`, a는 그 안의 국소 수준. 곡선과 그 밖 모수는 사전에서 따로 (상관 없음).
    ⑧ **기저 수를 바꿈 (계산 뒤, 2026-10-29).** 명세의 r 7·ℓ 8개는 S30 1단계에서 r 매듭 범위만 바꿔도 3% 컷이 0.57% 움직여(사후 sd 약 0.2%) 기저가 성긴 것으로 보고, P-스플라인의 표준대로 넉넉한 기저 + 벌점(Eilers·Marx 1996)인 **r·ℓ 12개씩**으로 올렸다
    (7 → 12에 10% 컷이 S30 +0.7%·S34 +3.5%). 범위는 0.1~40% 그대로 — 0.01~100%는 사슬이 갇혔다. RW2는 비중심화(c = m + L(τ)ζ — 처음 판은 0.1% 끝에서 발산 3~27). 12개·비중심화로 S30·S34 발산 0. 조정 시즌의 1단계 값만 본 결정이고 정답은 안 봤다.
    ⑨ **1단계는 라플라스 (C4, 계산 뒤, 2026-10-29).** 기저 12개 NUTS는 S19 한 시즌에 37분이고 재시도 뒤에도 ESS 236이라 24시즌에 약 15시간. 1단계가 넘기는 것은 사후 평균·공분산뿐이라
    MAP(float64, 반복 1,500, 안장점이면 음의 고유방향으로 밀어 다시) + 역 Hessian으로 바꿨다. 같은 칸 NUTS와 견줌 (S30·S34): 목표 컷 중앙 차 0.03~0.06%, S34 10%만 −0.33% (80% 폭의 0.3배), sd 비 0.79~1.36 (중앙 1.0).
    eps·phi는 사전 평균에 고정. 24시즌 합 약 12분, 모두 양정치 (S19·S24는 안장점 탈출 뒤).
    ⑩ **주성분은 관심 구간에서 (계산 뒤 — 1단계 값만 봄, 2026-10-29).** 24점 그대로 내면 제1 성분이 r(40%)·ℓ(u ≤ 0.05)에 쏠렸다 (S42 창: r(40%)에 0.92) — 목표·남은 시간과 무관한 끝의 시즌 차이.
    가중 내적 FPCA(Ramsay·Silverman 8장, 0/1 무게)로: 띠 = r 0.3~13.5%(w12 2~9번) · ℓ u ≥ 0.089(u12 2~11번)에서 PACE, 띠 밖 몫은 창 시즌 곡선을 띠 점수에 회귀해 잇는다. 창 고르기 밀도도 띠에서.
    ⑪ **r에 3% 매듭 하나 더 (계산 뒤, 2026-10-29 — 관측 규칙으로 고름, 정답은 보고만).** 1단계 4.3 점검에서 한섭 A 잔차가 3%를 지나며 부호를 바꿨다 (2~3% 평균 z +0.38 · 3~4% −0.66 — 곡선이 3%의 꺾임을 펴 버림).
    r 기저 12 · 20 · 12 + w = 0 매듭(13)을 조정 6시즌 1단계 PSIS-LOO로 견줘(7절 ④ 규칙: 합 차 > 2 SE, 통과한 것 중 단순한 쪽) **13**을 골랐다 (12 대비 +409 ± 39, 20은 +336 ± 43; k̂ > 0.7 줄이 많아 크기보다 방향이 근거).
    **낙관 위험:** 3% 매듭이라는 생각은 정답 곡선 비교(4.3, 보고만 — 5%에서 |e| 2~5%)를 본 뒤에 나왔다. 고르기 자체는 관측만 썼지만 WP5 사전 고정의 「이미 본 것」에 넣는다. 결과 `r7/wp3b_m3/check43_D1.md`.
    ⑤ 맞춤은 M1과 같이 MAP + 라플라스 아핀 재매개화 위 NUTS (`m1.map_precond` 꼴). 1단계 침수·컷 평활 τ는 로그로 함께 맞춘다. ⑥ 지연 키: 1단계도 칸도 그 시즌의 `expanding[s]` (앞 시즌만, S19·S20은 전체 값). ⑦ x항 β는 기본 뺌 — M1 ②가 「넣음」이면 1단계부터 다시.
- **세 후보가 다른 자리는 곡면의 유연성과 그것을 앞 시즌에서 빌리는 법뿐이다.** 관측 층·시즌 사이 층·좌표·채점은 같다 — 결과 차이를 곡면 꼴로 돌릴 수 있게.

| a (ln 3% 컷) | N(ln 100, 1.5²) | τ_a 0.3 |

   ① 침수 f2pow 대 Kumaraswamy ② x항 β 넣음 대 뺌 ③ 컷 기울기 직선 대 2차 (r0 + r1·w + r2·w²).

- **WP3b M1 세션이 더함 (2026-10-29, ④를 판정하기 전 — 조정 6시즌 1단계 첫 시도가 수렴 1/12였던 까닭).**

### WP4 관측 층 빼 보기 — 조정 시즌에서 먼저, 최종은 WP5 안에서

「자료 종류마다 얼마나 기여하나」를 숫자로 답한다. 고른 곡면(조정 시즌에서 가장 나은 M) 하나에 관측 층만 바꿔 돌린다.

| 변형 | 무엇을 보나 |
|---|---|
| A만 | 정확한 점만으로 어디까지 가나 |
| A + B | 말한 시각의 몫 |
| A + B + C (시각 모형) | C를 치우침째 담은 몫 — 본안 |
| A + B + C (게시 시각에 둠) | F의 방식으로 C를 쓰면 얼마나 나빠지나 |
| 본안 + 글로만 적은 % | 글의 몫 (1c 결과와 함께 넣을지 정함) |
| 본안 − 오염 혼합 | 엉뚱한 값 처리의 몫 |
| 본안, 서버 혼합 대신 mono 거르기 | 미상 줄을 확률로 쓰는 몫 |

  - **G1은 멈추지 않는 보고다** (사용자 2026-10-28). WP1과 WP3a 중 나중에 끝나는 세션이 이 문서에 「G1 보고」 절(몇 줄)을 쓰고 마지막 답에 같은 요약을 남긴 뒤 그대로 끝낸다.
    WP2·WP3b는 사용자 답을 기다리지 않고 WP1·WP3a가 끝나면 시작한다. 사용자가 나중에 의견을 주면 그때 반영하고 바꾼 곳을 적는다.
  - **G2만 사용자를 기다린다** — 결과를 보고 어떤 방법을 쓸지·다음 길을 사용자가 정한다 (WP6).
- **동시에 도는 세션 수.** WP1·WP3a는 둘 다 WP0만 기다린다 — 2세션 병렬. 그 뒤 WP2 1세션 + WP3b 최대 3세션.

## 7. 세션·에이전트 운영

- **세션 종류.** 조율 세션 (이 문서·진행표·사전 고정·G 보고 담당) · 작업 세션 (WP 하나).
- **에이전트에게 주는 것.** 읽을 파일, 입력·출력 경로, 완료 조건, 하지 말 것(운영 코드·모델 파일·글 번호). 결과는 파일로 쓰고 요약은 짧게 돌려받는다.
  작업 세션은 에이전트 결과를 원자료 몇 줄로 직접 확인한 뒤 커밋한다.
- **겹치지 않게.** 같은 파일을 두 세션이 고치지 않는다 — 진행표의 「맡은 파일」. 문서는 자기 WP 절과 진행표 줄만 고친다. push 전에 언제나 `git fetch origin main && git merge origin/main`.
- **계산.** 4코어·15GB (2026-10-28 확인). 긴 계산은 백그라운드로 돌리고 칸당·전체 시간을 적는다. 컨테이너는 세션이 끝나면 사라진다 —
  중간 결과는 커밋하거나 다시 만드는 명령을 남긴다.
- **파일 자리.** 코드 `tools/solo_raid/lab7/` (공개 허용 목록에 걸림 — 글 번호·원문·닉네임 금지), 결과 `data/solo-raid/analysis/r7/` (AGENTS.md 예외에 적음).

## 8. 위험과 대응
