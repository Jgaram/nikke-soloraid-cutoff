# 솔로레이드 진행 중 시즌 (실시간 수집·예측 → 끝나면 보강)

2026-10-16 사용자와 정한 운영 방식. 앞으로 열리는 시즌(S42부터)은 **Sonnet 세션 하나가 시즌 하나를 처음부터 끝까지** 맡는다 (처음에는 Opus로 정했다가 같은 날 Sonnet으로 바꿈, 사용자 결정).

- **진행 중:** 목적은 진행 중 레이드 예측이다. 정해진 시점마다 수집 → 예측을 내고, 예측을 커밋하고, 세션 채팅에 요약한다.
- **끝난 뒤:** 지난 시즌 일괄 수집과 같은 「분석 데이터 보강」으로 바뀐다 — 종료 후 인증까지 받고, 데이터 점검·예외 처리, 분석 갱신, 자기 예측 채점.

수집·판독 방법은 [일괄 수집 지시문](solo-raid-backfill.md)의 「시즌 세션 지시문」(변수·받기·판독·합치기·원본 대기·멈출 때)을 그대로 쓴다.
이 문서는 시점·예측·끝난 뒤 순서만 정한다.

## 정한 것 (사용자 결정, 2026-10-16)

- **시작:** 사용자가 챌린지가 열릴 무렵 새 세션에서 `docs/solo-raid-live.md를 S{n}으로 실행해`라고 한다 (S42 시작 시점은 사용자가 정함). 모델은 Sonnet.
- **예측 시점:** 챌린지 시작(`c_start`) 뒤 **T = 12·18·24·36·48·72·96시간** (`data/solo-raid/analysis/criteria.json`의 T). 시점마다 그때까지 게시된 자료로 낸다.
- **예측 기록:** `data/solo-raid/S{n}/predict/T{T}/`(predict_run.sh 출력 그대로)를 커밋한다. 끝난 뒤 정직하게 채점하려는 것이다 (AGENTS.md 「결과물」 예외).
  push하면 공개 웹(<https://jgaram.github.io/nikke-soloraid-cutoff/>)의 「진행 중 시즌 예측」도 자동으로 갱신된다 (docs/publish.md).
  세션 채팅에는 결과 맨 위 5줄 요약과 등급, 「검증 안 된 예측」임을 적는다.
- **기본 도구:** 그때의 `predict_run.sh` 기본(prior·서버 미상 처리)을 그대로 쓴다. 진행 중에 결과를 보고 도구나 설정을 바꾸지 않는다.
  기본을 바꾸는 판정은 분석 문서의 기준(개발 시즌 8개 이상, `criteria.json`)으로만 한다.
- **시험 시즌이어도 예측은 낸다** (`split.py role S{n}` — S42·S43은 개발, S44·S46·S48 시험). 다만 끝난 뒤 채점·분석은 하지 않는다 (아래 「끝난 뒤」).
- **예외 처리:** [예외 처리 규칙](solo-raid-backfill.md#예외-처리-규칙)대로 세션이 판단해 `S{n}/discard.json`에 남긴다. 도구 코드는 고치지 않는다.
- 사이트·UA·작업자·간격은 일괄 수집과 같다 (디시·네이버 게임 라운지·블라블라링크, 자기 이름 UA, 작업자 4·간격 0.5초).

## 1. 준비

1. 공식 공지 아카이브 `notices/`에서 이번 솔로 레이드 공지(보스·기간)를 찾는다. 없으면 사용자에게 묻는다.
2. `$STATE/season.json`: `name`·`boss`·`start`·`end`, `c_start`(기본 3일차 05:00 — 공지가 다르게 말하면 그것, 근거를 README에), `e_start` = `c_start`,
   `e_end` = 종료 + 2일 05:00. `data/solo-raid/S{n}/README.md`를 만들고 「진행」 표에 시점별 줄을 적어 간다.
3. `python3 -I tools/solo_raid/split.py role S{n}`로 몫(개발/시험)을 README에 적는다.
4. 시점 예약: 지금 KST로 다음 시점(c_start + T, 5분 여유)마다 `send_later`를 건다 (한 번에 다음 하나만 걸고, 깰 때마다 다음 것을 건다).
   컨테이너가 바뀌어도 `state_sync import`로 잇는다 (일괄 수집 지시문 「1. 준비」).

## 2. 시점마다 (T = 12·18·24·36·48·72·96)

1. **받기:** 구간 `[지난 끝, c_start + T)`를 `run_window.sh`로 한 번 (첫 시점은 `[c_start, c_start + 12시간)`). Bash `run_in_background`(timeout 7200000).
2. **판독·합치기:** `raid-window` Workflow 4개(Haiku, 상시 허락) → `merge_obs.py`. `missing.txt`가 있으면 빠진 배치만 다시.
3. 내보내기 → 커밋(`S{n} 받기 T{T}`) → push.
4. **예측:** `bash tools/solo_raid/predict_run.sh "$DEST/state" {T} --out "$DEST/predict/T{T}"` (후처리 → 예측, 몇 초~1분).
   커밋(`S{n} 예측 T{T}`, `predict/T{T}/`와 후처리 파일) → push.
5. **채팅 요약:** `predict_T{T}.txt` 맨 위 5줄(한섭 1·3% 중앙·80% 구간·등급, 일섭·글섭 등급)과 경고(`!!`)를 그대로 옮기고, 받은 글·관측 수를 한 줄로.
   예측이 시점보다 늦게 나온 만큼(받기·판독 시간)도 적는다. 숫자를 고치거나 해석을 덧붙여 확신을 키우지 않는다.
6. 다음 시점 `send_later`. 받기·판독에서 멈추면 일괄 수집 지시문 「멈출 때」대로 하고 사용자에게 알린다 (403·429면 그 시즌 받기를 멈춘다).

## 3. 끝난 뒤 (e_end 이후)

1. **남은 구간:** `[지난 끝, e_end)`를 받고 판독·합치기 (종료 후 인증). 필요하면 원본 대기 실행 (일괄 수집 「5」).
2. **후처리:** `bash tools/solo_raid/post_all.sh "$DEST/state"` → 커밋.
3. **데이터 점검:** [일괄 수집 「7. 데이터 점검」](solo-raid-backfill.md#7-데이터-점검-s34-이하실시간)과 같다.
4. **수집 끝 표시:** `$DEST/collect_done.json` (`{"done": "KST 시각", "by": "세션 id"}`) → 커밋. 이 표시가 있어야 분석 도구가 이 시즌을 쓴다.
5. **개발 시즌만:**
   - [일괄 수집 「8. 분석 갱신」](solo-raid-backfill.md#8-분석-갱신)의 3~5와 같다.
   - 자기 예측 채점: `python3 -I tools/solo_raid/score_live.py S{n}` → `predict/score.json` 커밋, 표를 채팅에 옮긴다.
6. **시험 시즌:** 채점·분석을 하지 않는다. README·채팅에 정답 점·컷 수치를 쓰지 않는다 (예측 수치는 진행 중에 이미 낸 것이라 괜찮다).
7. README 「시즌 요약」을 채우고 (일괄 수집 형식 + 「예측」 칸: 시점마다 커밋 시각과 등급) 사용자에게 끝을 알린다.
