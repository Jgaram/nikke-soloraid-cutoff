# 공개 레포와 웹 (nikke-soloraid-cutoff)

2026-10-16 사용자 결정. 솔로레이드 **코드와 파이프라인**을 공개 레포로 나누고, 커트라인을 **웹**으로 보여 준다.
이 레포(nikke-community)는 비공개로 남아 정본이 되고, 수집한 자료도 여기에만 둔다.

| 무엇 | 어디 |
|---|---|
| 공개 레포 | <https://github.com/jgaram/nikke-soloraid-cutoff> (`main`: 코드·문서, `gh-pages`: 웹) |
| 웹 | <https://jgaram.github.io/nikke-soloraid-cutoff/> — 첫 화면(최종 컷 예측 · 지금 몇 %면 최종 몇 % · 지난 시즌 컷), `analysis.html`(분석 페이지) |
| 라이선스 | CC0 1.0 (사용자 결정) |
| 이름 | 처음 `nikke-solo-percent`로 만들었다가 같은 날 `nikke-soloraid-cutoff`로 바꿨다 (사용자 결정). GitHub가 옛 레포 주소는 넘겨 주지만 Pages 주소는 넘겨 주지 않는다 |
| 만드는 도구 | `tools/publish/build_public.py`(공개 레포 내용) · `tools/publish/site.py`(웹) · `.github/workflows/publish.yml`(자동 복사) |

## 정한 것

- **공개 범위는 솔로레이드 파이프라인만이다.** 문서 `docs/solo-raid-*.md`(새로 만든 것도 자동)·`community-access.md`와 이 문서를 공개한다.
  코드는 `tools/solo_raid/`·`tools/publish/`, 수집 단계 `experiments/2026-10-15-solo-raid-low-cost/`의 `tools/`·`README.md`다.
  그 밖에 `.claude`의 raid-vision 에이전트·워크플로, 설정 `split.json`·`criteria.json`을 공개한다.
  목록은 `build_public.py`의 `ALLOW`가 정본이다 (허용 목록 방식 — 새 파일을 공개하려면 여기에 더한다).
- **웹에는 숫자와 개수만 싣는다.** 원글 링크·글 번호·사진·닉네임은 넣지 않는다 (사용자 결정).
  근거는 컷 예측이면 「근거 커뮤니티 N명」(그 서버 예측에 쓴 사람 수), 지난 시즌 컷이면 출처 종류 「집계표」·「관측 곡선」으로만 쓴다 (2026-10-16 사용자 결정 — 서버를 합친 시즌 전체 관측 건수는 컷의 근거가 아니라서 뺐다).
- **시험 시즌 정답 컷은 공개하지 않는다.** `site.py`는 split 감시를 켜고 `split.load_seasons()`로만 컷을 읽는다.
  시험 시즌은 「잠김」으로 표시하고, 진행 중 예측의 채점(`score.json`)도 개발 시즌 것만 싣는다.
  공개 웹을 분석 세션이 읽어도 블라인드가 깨지지 않게 하려는 것이다. 최종 시험(할 일 3.7)이 끝나면 풀지 다시 정한다.
- **갱신은 Actions 자동 복사다.** 이 레포 `main`에 관련 경로(워크플로의 `paths`)가 push되면, `publish.yml`이 공개 레포 `main`과 `gh-pages`를 통째로 다시 만든다.
  공개 레포에 직접 커밋한 것은 다음 복사 때 사라진다.
  - 워크플로는 웹에 들어가는 자료(`analysis/`·`registry.json`·`seasons.json`·`split.json`·`S*/predict/`·`S*/state/season.json`)와 공개 코드·문서가 바뀔 때만 돈다.
    수집 중 `state/`·`runs/` 커밋에는 돌지 않는다 (2026-10-16 — 그날 `data/solo-raid` 커밋 137개 중 웹 자료를 바꾼 것은 11개였다).
  - 웹의 기준 시각은 **웹 내용이 바뀐 때**다. `site.py`가 넣는 자료와 페이지 틀로 지문(`data.json`의 `content`)을 만들고,
    지금 공개된 `data.json`과 지문이 같으면 그 기준 시각을 그대로 쓴다 (`build_public.py`가 `--prev`로 넘김). 그래서 내용이 그대로면 `gh-pages`에 커밋이 생기지 않는다.
    바뀌었으면 그 커밋(HEAD) 시각이다. 예전에는 `data/solo-raid` 아무 커밋 시각이라, 잠긴 시즌 README 커밋에도 시각이 움직였다.
  - 예측 파일·`season.json` 하나가 깨져도 그 파일만 빼고 Actions에 노란 경고를 남긴다. 지난 시즌 컷과 공개 레포 코드는 계속 갱신된다.

## 내보내기 전에 손보는 것과 검사 (`build_public.py`)

- 공개하지 않는 파일(AGENTS.md, 실험 기록, `data/` 등)로 가는 마크다운 링크는 링크를 풀고 글자만 남긴다.
- 특정 글을 가리키는 값은 가린다: 디시 글 번호(`board/gov/{번호}`, `no={번호}`, `글 {번호}`)와 첨부 파일명의 촬영 시각(`Screenshot_YYYYMMDD_HHMMSS`).
- 다음 중 하나라도 걸리면 아무것도 쓰지 않고 멈춘다. Actions run이 빨갛게 뜬다.
  - 사진·동영상·jsonl·csv·tsv 파일
  - 1MB가 넘는 파일
  - 가린 뒤에도 남은 글 번호와 디시 이미지 주소
  - 웹 파일 안의 커뮤니티 글 주소
- 원문, 사진, OCR 결과(`ocr.jsonl` 등 — 랭킹 화면의 닉네임이 들어 있음)는 허용 목록에 없으므로 나가지 않는다.

손으로 확인: `python3 -I tools/publish/build_public.py --out {임시}/pub --site {임시}/site`

## 웹 화면 (2026-10-16 사용자 결정)

첫 화면(`index.html`, `site_template.html`)은 위에서부터 셋이다. 서버(한섭·일섭·글섭)를 바꾸면 모두 바뀐다.

1. **최종 컷 예측** — 진행 중 시즌의 최종 1·3·10% 컷 점수(`S{n}/predict/`). 최근 시점의 칸·시점별 그래프·표, 등급과 「근거 커뮤니티 N명」, 예측 방법(예측 JSON의 prior 이름).
   - 등급 C·D는 가운데 숫자를 흐리게 하고 80% 구간을 앞에 둔다. 등급 사유 원문은 내부 용어라 싣지 않고 등급별 한 줄만 쓴다.
   - 끝났는지는 **브라우저가 종료 시각으로** 정한다 (만들 때 정하면 새 커밋이 없을 때 「진행 중」으로 남는다). 끝나면 제목이 「지난 예측」으로 바뀌고,
     개발 시즌은 `score.json`이 있을 때 실제 컷과 견준다. 시험 시즌은 「실제 컷 비교는 최종 검증 뒤」라고만 쓴다.
   - 새 시즌 `state/season.json`이 올라와 챌린지가 시작됐는데 예측이 아직 없으면 「첫 예측은 시작 6시간 뒤, 그 뒤 6시간마다 갱신」을 띄운다 (2026-10-16, 6시간 자동 수집 → docs/solo-raid-live.md).
     진행 중이면 예측 방법 줄에도 「6시간마다(한국 시간 05·11·17·23시까지 올라온 자료) 갱신」을 붙인다.
     진행 중 시즌은 분석 등록부(`registry.json`)에 아직 없으므로, `site.py`의 「최근 시즌」은 등록부와 함께 `S*/state/season.json` 폴더도 본다 (2026-10-16, S42에서 빠지던 것을 고침).
2. **지금 몇 %면 최종 몇 %?** — 분석 페이지 ①과 같은 계산기 (`viz.py`의 여러 시즌 평균 % 변환, 0.5시간 간격). 진행 중 시즌이 있으면 그 시즌 날짜와 지금 시각으로 보인다.
   시점별 표는 접어 둔다.
   - **시점 고르기는 한 줄 타임라인이다** (2026-10-16 사용자 결정 — 날짜는 드롭다운, 시간은 가로 슬라이더라 둘 다 시간 순서라는 게 안 보였다).
     슬라이더 하나가 챌린지 전체를 30분 칸으로 덮고, 바로 아래 일차 칸(진행 중이면 날짜도)이 같은 가로축에 붙는다. 칸을 누르면 하루 안의 시각은 그대로 두고 그날로 가고,
     ◀ ▶는 30분씩 움직인다(폰에서 끌기가 거칠어서). 진행 중 시즌이면 실제 지금 시각에 빨간 「지금」 선을 긋는다. 분석 페이지 ①도 같은 모양이다(시즌 시작일을 넣으면 날짜가 붙음).
   - **지난 시즌 실제 자료 겹쳐 보기** (2026-10-16 사용자 요청): 그래프 위 버튼 「끄기 · 전체 · 시즌」(기본 끄기, 브라우저에 기억)으로 둘을 올린다.
     - 관측 점: 개발 시즌 진행 중 순위 화면의 점수·% 하나에, 같은 점수의 최종 %를 끝난 뒤 점수표 곡선에서 붙인 것이다 — 그 사람의 최종 순위가 아니다.
       사람·일차마다 하나, 최종이 1·3·10%의 ÷1.3~×1.3인 것만, 숫자만 싣는다.
       점은 배율(최종 ÷ 그때)을 그대로 두고 「최종이 딱 t%였다면 그때 %」(t × 그때 ÷ 최종)에 찍는다 (2026-10-16 사용자 요청 — ÷1.3~×1.3 폭 탓의 흩어짐을 없앰.
       평균선 대비 흩어짐 한섭 627개 ×1.24 → ×1.17, 일섭 113개 ×1.27 → ×1.23 — 7개 시즌 기준). 풍선에는 원래 그때 %·최종 %·배율도 보인다.
     - 「그 시즌처럼 밀렸을 때」 점선: 여러 시즌 곡선 × 시즌 수준 배수 — 관측을 이은 선이 아니다. 시즌 하나를 고르면 계산기 문장에도 그 시즌 기준 값이 붙는다.
     - 자료는 `site.py`의 `conv()`가 viz의 개발 시즌만으로 만든다 (시험 시즌은 들어가지 않음).
3. **지난 시즌 커트라인** — 값마다 출처(집계표 / `*` 관측 곡선). 서버마다 자료가 있는 첫 시즌부터 보이고, 자료가 있는 시즌이 둘 미만이면 그래프 없이 표만. 아직 안 끝난 시즌은 숨긴다.
   - **한섭은 30% 컷도 참고로 싣는다** (2026-10-16 사용자 요청). 분석 시즌은 정답 표 값, 그 밖 개발 시즌은 `server_cutoffs.csv`(지금 S31만).
     일섭·글섭 30%는 집계표가 드물어 싣지 않는다. 30% 값이 있는 서버에만 열·선이 생기고, 시즌마다 크게 오르내리고 근거가 약하다는 문장을 붙인다.

- 정확도는 첫 화면에 싣지 않는다. **분석 페이지 맨 위 안내**에 「①·②는 여러 시즌 방법이고 첫 화면의 컷 예측은 다른 방법({prior 이름})으로 내며 그 정확도는 검증 중」이라고 쓴다.
  분석 페이지는 `viz_template.html`을 그대로 쓰되 공개용으로 부제·만든 도구 줄(비공개 경로)과 「아직 분석에 들지 않은 개발 시즌」 문장을 뺀다.
- **맨 아래 문구**는 두 페이지에 똑같이 붙는다 (`site.py`의 `FOOTER`, 2026-10-16 사용자 결정): 공개 레포 링크와 CC0의 범위(이 프로젝트가 만든 코드와 숫자만),
  출처(커뮤니티 이용자가 공개로 올린 순위 화면)와 예측이라 다를 수 있다는 말, 게임 권리(SHIFT UP · Level Infinite)와 비공식 팬 프로젝트라는 말.
- **웹 화면의 문장은 모두 합니다체(「~입니다」)로 쓴다** (2026-10-16 사용자 요청). 첫 화면(`site_template.html`)과 분석 페이지(`viz_template.html`·`viz.py`의 요약 문장·`site.py`의 안내)가 대상이고,
  표 머리·범례 같은 짧은 꼬리표는 명사형 그대로 둔다. 새 문장을 더할 때도 이 말투를 따른다.
- 폭 600px 아래에서는 보스·시작일·출처 칸을 숨기고(보스는 시즌 아래 작은 글씨) 구간을 둘째 줄로 내려 1·3·10%가 바로 보이게 한다.
- 손으로 확인: 위 명령으로 만든 뒤 Chromium(`/opt/pw-browsers`)으로 폭 1200·390px을 찍어 본다. 진행 중 예측은 끝난 시즌 state 사본에 `predict_run.sh --skip-post`로 만든 예측을 넣어 본다.

## 처음 설정 (사용자가 한 번 함)

1. **토큰:** GitHub → Settings → Developer settings → Fine-grained tokens → Generate new token.
   - Repository access: Only select repositories → `jgaram/nikke-soloraid-cutoff`
   - Permissions: Contents → Read and write
   - 만료일은 원하는 대로 정한다. 만료되면 복사가 빨갛게 뜨므로 새로 만들어 바꾼다.
2. **이 레포 Secret:** nikke-community → Settings → Secrets and variables → Actions → New repository secret.
   이름은 `PUBLIC_REPO_TOKEN`, 값은 1번의 토큰이다. 없는 동안 `publish.yml`은 아무것도 하지 않고 초록으로 끝난다.
3. **Pages:** nikke-soloraid-cutoff → Settings → Pages → Build and deployment → Source: Deploy from a branch → `gh-pages` / `/ (root)`.
4. 처음 한 번은 Actions → publish → Run workflow로 돌린다. 그다음부터는 push마다 돈다.
